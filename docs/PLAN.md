## 1. 第5類の8分音符 [x]

**目的** 第5類(華麗対位法)で、弱い4分拍を2つの8分音符で飾れるようにする。フックス/イェッペセンの扱いに従い、使える場所と動き方を厳しく限る。

**理論(変えない)**
- 8分音符は**2つ1組**で、1つの4分音符の位置(弱い4分拍=第2拍または第4拍。`b` が 1 または 3)を置き換える。第1拍・第3拍には置かない。
- 2つとも**順次進行**で入り、順次進行で出る(前の音→1つ目、1つ目→2つ目、2つ目→次の音が、すべて2度)。跳躍で入る・出るのは誤り。
- 不協和は、順次進行である限り、1つ目にも2つ目にも置ける(経過音・刺繍音として)。拍頭の協和の規則(`dissonance`)は8分音符には適用しない(拍頭に来ないため)。
- 下行の8分音符を基本とする。上行は誤りではないが、注意(warn)にする。
- 最初の小節と最後の2小節(終止の準備と終止)には使わない(誤り)。
- 1曲に8分音符の組が3つ以上あれば注意(多すぎる)。
- 掛留の準備になる音(`tieNext` のスロット)の直前の4分拍にも置ける(準備の音へ順次で入ればよい)。

**仕様**
1. `engine.js`
   - `PATTERNS` に追加: `hqee`:[2,1,½,½]、`qeeh`:[1,½,½,2]、`qeeht`:[1,½,½,2]+tie、`qeeqq`:[1,½,½,1,1]、`qqqee`:[1,1,1,½,½]。ラベルは「2分音符+4分音符+8分音符2つ」のように日本語で。
   - `PAT_MID` にこの5つを足す(`PAT_FIRST` には足さない。最初の小節では使わない)。`buildSlots` は `dur` 0.5、`b` が 1.5 や 3.5 のスロットを作る(`skey` は `"m:1.5"` でよい)。
   - `analyze` に規則を足す。`RULES` に `eighthStep:'8分音符の順次進行'`、`eighthPlace:'8分音符の位置'`、`eighthUp:'8分音符の上行'`、`eighthMany:'8分音符が多すぎる'`。
     - `eighthStep`(err): 組の前後と組の中の3つの進行のどれかが2度でない。`cols` はその組の2スロットと、問題の隣の音。
     - `eighthPlace`(err): 組が最初の小節・最後の2小節にある。(パターン選択の時点で防ぐが、保存データの読み込みに備えて判定も持つ。)
     - `eighthUp`(warn): 組が上行(1つ目→2つ目が上)。
     - `eighthMany`(warn): 組が3つ以上。
     - 弱拍の不協和の判定(`weakdis`)で、`dur===0.5` のスロットは「順次で入り順次で出る」なら不協和でも通す(`dis[i]` は「経」または「刺」を付ける。刺繍音=前後が同じ音)。
   - `INJECT` に `eighthStep:[5]` を足す(復習で出題できるように)。
   - `solve`: 候補を作る所で、`s.dur===0.5` のときは前の音と2度の音だけを候補にする(今は不協和のときだけ `ad===1` を要求している)。
   - `defaultRhythm` は変えない(8分音符は利用者が選ぶ)。
2. `score.js`
   - `DUR[0.5]='8'` は既にある。組ごとに `new VexFlow.Beam([n1,n2])` を作って描く(符尾の向きは Beam に任せる)。空きスロット(GhostNote)と組む場合は連桁を付けない。
   - `slotL`/`slotR`(枠の左右)は今の「隣との中点」のままでよい。
3. `app.js`
   - `rhythmIcon` で `d===0.5` を描く(塗りつぶした符頭2つを連桁でつなぐ)。
   - 第5類のリズム選択で、`qeeht` は `s.m > n-3` のとき無効(既存のタイの扱いと同じ)。8分音符を含むパターンは `s.m===0` と `s.m>=n-2` で無効にし、ボタンの `title` に「最初の小節と終止では使えません」。
   - 再生(`playAll`)は `b` が小数でも正しく鳴ることを確かめる(計算は `(m*4+b)*q` で既に小数対応)。
   - 規則の引き出し(`RULE_TEXT[5]`)の「8分音符にはまだ対応していません。」を、上の理論を要約した2行に置き換える。
4. `test/engine.test.js`
   - 順次の8分音符(経過)が err なし、跳躍で入る8分音符が `eighthStep`、第1拍に置いたパターンは作れない(`PAT_MID` にない)、小節の拍数の合計が4、`solve` が `qeeh` を含むリズムで解を返す。

**受け入れ条件**
- 第5類で、第2小節に「4分+8分×2+2分」を選ぶと、8分音符2つが連桁付きで描かれ、クリックで音を置ける。
- 8分音符に跳躍で入ると「8分音符の順次進行」の誤りが出る。順次の経過・刺繍なら誤りが出ず、音程の行に「経」「刺」が付く。
- 「解答例と比べる」が、8分音符を含むリズムでも解を返す(3秒以内)。
- 再生で8分音符が正しい長さ(4分音符の半分)で鳴る。
- 保存→記録から開く→同じリズムで復元される。

**未決**

**実装メモ**
- engine.js: `PATTERNS` に `hqee`・`qeeh`・`qeeht`・`qeeqq`・`qqqee`、`PAT_MID` に追加、`hasEighth(id)`。`buildSlots` は変更不要(`b` が 1.5・3.5 のスロットができ、`skey` は "m:1.5")。
- `analyze`: 第5類で、同じ小節の連続した `dur 0.5` 2つを1組とし、`eighthPlace`(最初の小節・最後の2小節)、`eighthStep`(前→1つ目、1つ目→2つ目、2つ目→次 のどれかが2度でない)、`eighthUp`(上行、warn)、`eighthMany`(3組以上、warn)。不協和の8分音符は、順次で入り順次で出れば「経」(同方向)または「刺」(折り返し)。刺繍音の判定を `dur<=1` に広げた。順次でない不協和の8分音符は `weakdis` を出さず `eighthStep` にまとめる(二重に出さないため)。
- `solve`: 8分音符の候補は前の音から2度だけ。`STRICT` に `eighthUp`・`eighthMany`(下行を優先)。`makeQuestion('eighthStep')` は第3小節を `hqee` にしたリズムで出題。
- score.js: 組ごとに `VexFlow.Beam`(対旋律の色。`setStyle` が効かないので描く前に `ctx` の色を設定)。app.js: リズムのアイコンに連桁、8分音符を含むパターンは最初の小節と最後の2小節で無効(理由を title に)、拍の表示「4拍目の後半」、第5類の小節幅を 184→204、規則の引き出しの文言。
- 確かめたこと: テスト5件追加(順次の組は誤りなし、跳躍で入ると eighthStep、終止で eighthPlace、刺繍の「刺」、4種のリズムで solve が解を返す、復習問題が作れる)。画面で `hqee` を選び解答例を採用→誤りなし・連桁1本、再生、記録からの復元は既存の仕組みで rhythm を保存。

## 2. 小ドリル(「ドリル」タブ) [x]

**目的** 1曲を書く前の基礎固め。1問数秒で答えられる形式で、規則の個々の要素(音程、進行、不協和の種類、終止、変化音)を反復する。

**全体の仕様(2a)**
1. タブを「練習 / ドリル / 復習 / 記録」にする(`data-view="drill"`)。スマホ幅でもタブが1行に収まること。
2. `js/drills.js` を新設(読み込み順は `engine.js` の後、`score.js` の前)。**純粋な出題部**: `GD.DRILLS` = `[{id, title, desc, make(opts) → q}]`。`q` は
   ```
   {kind:'choice', prompt:文, score:{cf:[..], cp:[..], above, sp, rhythm?, ties?} | null,
    play:'dyad'|'all'|null, hideScore:bool, choices:[{label, ok:bool}], explain:文, focus:[slot…]}
   ```
   `score` は `GScore.engrave` にそのまま渡せる最小の model(定旋律1〜4小節)。`choices` は常に4つ、正解は1つ。乱数は `GE.pickOne` などを使い、DOM には触れない。
3. `app.js` に `drawDrillPanel`/`drawDrillStage` を足す。画面構成:
   - 上: ドリルの一覧(横並びのチップ。選ぶと出題が始まる)。各チップに「正解 12/15」の小さな成績。
   - 中(楽譜カードの位置): 問題の楽譜(`hideScore` なら伏せ、答えた後に表示)と「▶ 聴く」ボタン。
   - 右パネル: 問題文、選択肢ボタン4つ、答えた後に「正解/不正解」と `explain`、「次の問題」。キー `1`〜`4` で選択、`Enter` で次へ。
   - 連続正解数を表示。
4. 成績は `store.drillStats[id] = {n, ok, streak, best, t}` に保存(`persist`)。書き出し/読み込みに含める。「記録」タブの「よく間違える規則」の下に「ドリルの成績」一覧を足す。
5. 楽譜の表示は `GScore.engrave(model)` を使い、`drawStaffVF` の「VexFlow の SVG + 小節番号」だけの簡易版 `drawSnippet(svgEl, model, opts)` を作る(選択枠・音程の行は出さない。`opts.marks` で指定したスロットに `t-focus` の枠を出す)。

**各ドリルの仕様(2b〜2i)**。理論の線引きは `engine.js` の判定をそのまま真とする(ドリル側で規則を二重に書かない)。

- **2b 音程当て(目で見る)** `iv-eye`: 定旋律1音と対旋律1音(全音符、1小節)。問い「この音程は?」。選択肢は `質+度数`(例「長6度」)。正解と、同じ度数の別の質、±1度の音程、から4つ。複音程はそのまま(「長10度」)。範囲: 同度〜12度、増減音程も出す(増4度・減5度・減7度など、`interval` が返すもの)。`explain`: 「D4 と B4 は、D-E-F-G-A-B で6度。長音階の第6音と同じ距離なので長6度です。」の形(度数の数え方+質の根拠を1文ずつ)。
- **2c 音程当て(耳で聴く)** `iv-ear`: 2b と同じ出題で `hideScore:true`、`play:'dyad'`(2音を同時に鳴らす)。範囲は3度〜10度の協和音程と、増4度・減5度・2度・7度。答えた後に楽譜を表示。
- **2d 進行の種類** `motion`: 定旋律2音+対旋律2音(第1類2小節、協和のみ)。問い「2つの声部の動きは?」。選択肢「反行・斜行・並行・平行」(固定4つ)。正解は `GE.motion` と `analyze` の `mo` の区別に合わせる(同度数の完全協和の並行=平行)。`explain` に、それぞれの定義を1文。平行5度・8度のときは「これは禁じられた平行5度です」を足す。
- **2e 不協和の種類分け** `dis-kind`: 第2類または第3類の1〜2小節を `GE.solveFor` で作り(定旋律はフックスか生成)、`analyze` の `dis[]` が「経」「刺」「カ」のスロット、または `weakdis` の誤りを1つ仕込んだスロットを問う。`focus` にそのスロット。選択肢「経過音・刺繍音・カンビアータ・誤り(どれでもない)」。掛留は 2g で扱うので出さない。`explain` は `analyze` の `x` を流用。
- **2f 平行5度を耳で探す** `par-ear`: 第1類4小節(定旋律の一部を切り出し、`solveFor` で対旋律を作り、第2〜4小節のどこか1か所に平行5度または平行8度を仕込む。仕込めない場合は作り直す)。`hideScore:true`、`play:'all'`。問い「平行5度(8度)はどこ?」。選択肢「1→2小節・2→3小節・3→4小節・ない」(「ない」が正解の問題も1/4の割合で出す)。答えた後に楽譜を表示し、該当箇所に枠。
- **2g 掛留の連鎖** `susp`: 第4類3小節を `solveFor` で作り、掛留の**解決音**を1つ伏せる(その位置に `GhostNote`、枠)。問い「掛留 ○-○ の解決音は?」(例「7-6」)。選択肢は音名4つ: 正解(2度下)、2度上、同じ音(解決しない)、3度下。`explain`: 「掛留した不協和(7度)は2度下行して協和(6度)に解決します。上声の掛留は 7-6・4-3・9-8。」
- **2h 終止の型** `cadence`: 旋法と対旋律の位置をランダムに選び、定旋律の最後の2音を示す(2小節)。問い「対旋律の最後の2音は?」。選択肢は「C♯5 → D5」のような音名の組4つ: 正解(`solveFor` 第1類の最後2音)、導音の♯を落としたもの(フリギア・イオニア・リディアでは代わりに「♯を付けたもの」)、終止音へ跳躍するもの、5度→8度(隠伏)。`explain` に旋法ごとの終止形(上: 長6度→8度、下: 短3度→同度、フリギアは導音を上げない)。
- **2i ムジカ・フィクタ** `ficta`: 2小節の対旋律の断片を示し、1音に枠。問い「この音に♯(または♭)は必要?」。選択肢「♯が必要・♭が必要・そのままでよい・どちらでもよい」。出題の型は3つ: (1) 終止の導音(ドリア・ミクソリディア・エオリアは♯が必要、フリギア・イオニア・リディアはそのまま)、(2) 旋律の輪郭が F〜B の三全音になる B(♭が必要)、(3) 変化音の必要がない途中の音(そのまま)。「どちらでもよい」は正解にしない(選択肢の数合わせ)。`explain` は、規則の引き出しの「終止」「変化音」の文を流用。

**受け入れ条件**
- 「ドリル」タブで8種類すべてが出題され、答えると正誤と説明が出て、「次の問題」で続く。
- 2c・2f は答えるまで楽譜が伏せられ、「▶ 聴く」で音が出る。
- 成績が記録タブに出て、書き出し→読み込みで戻る。
- `node test/engine.test.js` に、各ドリルの `make` を50回呼んで、正解がちょうど1つ・選択肢が4つ・`score` が `analyze` で壊れない(例外なし)ことを確かめるテストを足す(`drills.js` も Node で読めるよう `GE` と同じ公開方法にする)。

**未決**
- 2f の「ない」の割合(1/4 でよいか)。
- 2b の増減音程を初期設定で出すか、設定で切り替えるか(今は出す)。

**実装メモ**
- `js/drills.js`(新設、`GD`): 8種類の `make`。問題の `score` は `{sp, above, cf, slots, vals, marks, hide, pre}`(仕様の形を少し広げた: 抜粋した小節のスロットを直接持つ。最後の小節が全音符に変わらないよう `buildSlots` を通さない)。抜粋は `GD.excerpt`。Worker の `drill` タスクで作る(第3類・第4類の解答探索を伴うため)。
- 答えの偏りを避けるため、狙う答えを先に決めてから作る(不協和の種類、平行を聴く)。カンビアータは解答探索ではほとんど出ないので、解答の1小節に型を書き込んで、`analyze` が「カ」と判定し、その前後の小節に誤りがないものだけを使う。50問での分布はおおむね均等(経過音・刺繍音がやや少ない)。
- 画面: タブ「練習 / ドリル / 復習 / 記録」。ドリルの一覧(成績つき)、楽譜(`drawSnippet`。`hideScore` なら答えるまで伏せる)、▶ 聴く、右パネルに問題・選択肢・正誤と説明。キー 1〜4 / Enter / Space。成績 `store.drillStats` は書き出し・読み込みに含まれ、記録タブに一覧。
- 楽譜フォントの CSS を `#staff .vfw text` から `.vfw text` に広げた(ドリルの楽譜で文字化けしたため)。
- テスト: 全ドリルで、選択肢4つ・正解1つ・ラベルの重複なし・`analyze` が例外を出さない。
- 未決への回答(実装した値): 2f の「ない」は 1/4。2b は増減音程も出す(切り替えは未実装)。

## 3. 穴埋め課題 [x]

**目的** 完成した解答の一部だけを自分で埋める、1曲より軽い練習。終止の型や掛留の形など「決まった形」を手で覚える。

**仕様**
1. 練習タブの操作バーに「穴埋め」ボタン(`#fillBtn`)。押すと、今の類・定旋律・位置で `task('solve')` を呼び、解を取って**2〜3スロット**を空にする(選び方: 最後の2小節から1つ、途中から1〜2つ。最初の小節・休符・タイで続く側は選ばない。第4類なら掛留の解決音を優先)。
2. `state.fill = {locked:Set(skey…), blanks:[skey…], answer:cp}` を持つ。`locked` のスロットは `setNote`・MIDI・矢印で変えられない(クリックすると「この音は固定です」のトースト)。`blanks` のスロットは `t-sel` と同じ色の点線枠で常に示す。
3. 右パネルに「穴埋め課題: 空いている3か所を埋めてください」と「答え合わせ」「ヒント(1か所だけ正解を入れる)」「やめる(元の解答に戻す)」。答え合わせ: すべて埋まり、`analyze` に err がなければ正解(解答例と同じ音でなくてよい)。正解時に `store.stats` には記録せず、`store.drillStats['fill']` に記録。
4. 穴埋め中は「解答例と比べる」「消去」「新しい定旋律」「類・位置の変更」を無効にする(押すと穴埋めをやめるか確認する簡易ダイアログ=トースト+もう一度押すと実行、`armDelete` と同じ方式)。
5. 穴埋めを始める前の解答は `stash` と同じ方法で退避し、「やめる」で戻す。

**受け入れ条件**
- 第1類で「穴埋め」→3か所が空く→埋めて「答え合わせ」で正解/不正解が出る。固定の音は変えられない。
- 第4類で、空く場所に掛留の解決音が含まれる(10回中8回以上)。
- 「やめる」で元の解答に戻り、Undo の履歴も元のまま。

**未決**

**実装メモ**

## 7. 採点(授業用の罰点表を土台に) [x]

**目的** 根拠の弱い「100点−誤り10−注意3」をやめ、授業で実際に使われている罰点の付け方(Nancy Rogers, FSU の Species Counterpoint Grading Guidelines。誤りの重さで3・2・1点を引き、くり返しで重くなる項目と全体への減点がある)に合わせる。合否(誤り0なら合格)も並べて出す。2026-11-17 利用者が「A を土台」と決定。

**理論(変えない)** 規則ごとの点数:
- **3点**: `parallel`(平行5度・8度)、`antiparallel`(反行による連続5度・8度)
- **2点**: `hidden`(隠伏5度・8度)、`dissonance`(強拍の不協和)、`weakdis`(弱拍の不協和の扱い)、`susp`(掛留の解決)、`prep`(掛留の準備)、`beatpar`(拍頭間の平行)、`eighthStep`(8分音符の順次進行)
- **1点**: それ以外のすべての規則(跳躍の禁則、交差、開始・終止、導音、同度、音域、埋め合わせ、変化音、同音反復、頂点、リズム、8分音符の位置 など)
- **くり返しで重くなる**: `run`(同じ種類の3度・6度の連続)は「連続数−3」点(4つで1点、5つで2点)。
- **全体への減点**: 途中の拍頭の完全協和の割合(`stats.perf ÷ (小節数−2)`)が 1/2 を超えれば2点、1/3 を超えれば1点(「完全協和の使いすぎ」)。
- 合計は減点の和(満点の考え方はとらない)。**合格** = 書き終えていて `err` が0。

**仕様**
1. `engine.js` に `POINTS`(規則 → 点)と `grade(r, ctx)` を足す。返り値 `{total, items:[{id, t, pts, cols}], global:[{t, pts}], pass, complete}`。`r` は `analyze` の結果。
2. 画面: 判定の見出しは今のまま「誤り n · 注意 n」。その下に「減点 N(3・2・1点の罰点表)」と、合格なら「合格」の札。指摘の一覧の各行に「−3」などの点。全体への減点は一覧の最後に1行。規則の引き出しに「採点のしかた」の節。
3. 保存: 記録の各解答に `pts`(減点の合計)と `pass` を加える。一覧の表示は `pts` があれば「−N」と合否、なければ(古い記録)今の点数。
4. テスト: 平行5度1つで3点、隠伏で2点、跳躍の禁則で1点、3度が5つ続くと2点、完全協和の多い解答に全体減点、誤りのない完成した解答が合格。

**受け入れ条件**
- 平行5度を1つ含む解答の減点が3、指摘の行に「−3」が出る。
- 誤り0の完成した解答に「合格」が出る。

**実装メモ**
- engine.js: `POINTS`(3点・2点の規則。ほかは1点)と `grade(r, ctx)`。`run` は「連続数−3」点、完全協和の割合で全体減点(書き終えたときだけ)。
- app.js: `scoreOf` が `grade` を返す。判定の見出しの下に「減点 N」と合格の札、指摘の各行に「−N」、全体減点は一覧の最後。保存する記録に `pts`・`pass`。古い記録(`score` だけ)は今までどおり点数を表示。規則の引き出しに「採点のしかた」。
- 確かめたこと: テスト1件(平行5度3点、隠伏2点、正しいフックスの例が合格、3度5連続で2点、完全協和だらけで全体減点)。画面で、例の解答が「減点 7」、解答例を採用すると「合格・減点 0」、記録の一覧に「−0 合格」。
- 確認(2026-11-18): 「反行による連続5度・8度」は罰点表で平行と同じ3点の誤りだが、判定が「注意」だったため、これを含む解答も合格になっていた。罰点表に合わせて `err` に変更(解答探索の `STRICT` からは外した。`err` なので常に避けられる)。テストを追加。
- 気づいた点: 隠伏5度・8度は出典では「上声が跳躍して入るとき」だけ2点。このアプリの判定は跳躍に限らず並行で完全協和に入るものすべてを誤りにしているので、2点を一律に付けている(判定の線引きは変えていない)。
