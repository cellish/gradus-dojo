```

├── src/gradus.html         分割前の1ファイル版(v5, 参照用・編集しない)
├── app/                    配布物(PWA・Claude上のページ共通)
│   ├── index.html          画面の骨組み(HTML)
│   ├── css/app.css         見た目
│   ├── js/score.js         楽譜の浄書(VexFlow 5)。座標を返し、重ね表示は app.js が描く
│   ├── vendor/             VexFlow 5.0.0 とライセンス文(編集しない)
│   ├── js/engine.js        純粋な計算部(DOMに触れない): 音程・判定・解答探索・定旋律生成・復習問題生成
│   ├── js/worker.js        engine.js を読み込み、重い計算を裏で実行する Web Worker
│   ├── js/app.js           画面・操作・保存・音・MIDI
│   ├── manifest.webmanifest, sw.js, icons/, README.md
└── test/engine.test.js     engine.js の単体テスト(node test/engine.test.js)
```

### 設計の約束ごと
- **engine.js は DOM・localStorage・state に触れない。** ブラウザ本体・Worker・Node のどこでも動くこと。`globalThis.GE` に公開し、Node では `module.exports`。
- 重い処理(`solve`・定旋律生成・復習問題生成)は Worker 経由で呼ぶ(`task(type,args)` が Promise を返す)。Worker を作れない環境では本体スレッドで同じ関数を実行して代替する。
- 音の表現は `{s, a}`。`s` = オクターヴ×7 + 音名番号(C=0…B=6)、`a` = 臨時記号(−1/0/+1)。C4 = 28。
- 対旋律は「スロット」(小節 m・拍 b・音価 dur)の並び。値は `cp["m:b"]` に保存。タイで続く側のスロットは編集不可。
- 判定結果 `issues[]` の各要素: `{id, lv:'err'|'warn', cols:[slot index…], t:見出し, x:説明}`。`id` は `RULES` のキー(復習の集計に使う)。
- 保存キー: localStorage `gradus-v2`。構造 `{drafts, prefs, history, stats, cfs, cfSeq}`。旧 `gradus-drafts-v1` は読み込み時に移行。**キー名と構造を変えるときは移行処理を書く。**
- Claude上のページでは、ダウンロード・MIDI・マイク・Service Worker が使えない。機能は「使えなければ隠す/代替する」で作る。

### 公開手順
1. `node test/engine.test.js` が通ること。
2. ブラウザで `app/` を開いて確認(`python3 -m http.server` で `app/` を配信)。
3. Claude上のページ: claude-artifacts の publish_files で `app/` の index.html・css・js を同じ slug に再公開(manifest・sw・icons は不要)。
4. PWA: `sw.js` の `CACHE` の番号を上げ、`app/` をZIPにして渡す。

### 段階1.5 楽譜表示を VexFlow に置き換える(2026-11-17 実装・公開済み)
利用者の指摘: 今の手描きSVGの楽譜表示は少し変(具体的にはト音記号・ヘ音記号の大きさと位置)。
→ 2026-11-17 音部記号は修正済み: 文字の外枠(getBBox)ではなく、canvas の measureText の実際の形(actualBoundingBox)で測って配置。ト音記号の目標位置が大譜表の間の余白(GAP)を誤って含んでいたのも修正。
VexFlow 化は、8分音符・浄書の質・リハモ道場との統一のため、引き続き候補。リハモ道場は2026-11にVexFlowへ切り替え済みなので、同じ方式にそろえる。

**今の表示の弱点**
- 符頭・符幹・タイ・休符・臨時記号を座標で手描きしている。定旋律と近い音は対旋律を15pxずらすだけなので重なりが不自然。
- 定旋律と対旋律が1つの大譜表を共有し、どちらの声部がどの譜表か曖昧。音部記号はフォント文字を計測して置いている。
- 連桁・旗・8分音符を描けない(第5類の8分音符を足すには描画の作り直しが必要)。

**VexFlowにすると**
- 浄書の質(符幹の向き、臨時記号の間隔、タイ、休符、連桁)がそろう。第5類の8分音符もそのまま描ける。
- 声部ごとに1段ずつの譜表にでき、音部記号を声域で選べる(将来、フックス原典のハ音記号表示も可能)。
- リハモ道場と描画の作りがそろい、保守が楽になる。

**作り方**
- 新しい `js/score.js` に `renderScore(svg要素, モデル) → 座標情報` を作る。モデルは定旋律・スロット・対旋律の値・臨時記号・タイ・空きスロット。
- 小節ごとに Stave を固定幅で並べ(上の段=上声、下の段=下声)、各小節で両声部の Voice を `Formatter.joinVoices().format()` で縦にそろえる。空きスロットは GhostNote で幅だけ確保する。
- 描画後に各音の x(`getAbsoluteX`)と、譜表の線の y(`getYForLine`)を取り出して返す。選択枠・誤り/注意の色・音程と進行の行・平行線・最高音の印・候補の点・解答例の重ね表示・クリック位置→音高の換算は、すべてこの座標から app.js 側で描く(今の drawStaff の重ね表示部分を移植)。
- 解答例の音は別の Voice(色付き・白抜き)として同じ譜表に重ねるか、app.js 側で座標から描く。
- VexFlow が読み込めなかったときは今の手描き表示に切り替える(しばらく残す)。
- 版はリハモ道場と同じものにそろえる(要確認。4.2系なら UMD の `vexflow.js` が `Vex` を公開)。PWA は `js/vendor/` に同梱してオフラインでも動かす。Claude上のページは同梱ファイルか cdn.jsdelivr.net/npm から読む。

**実装メモ(2026-11-17)**
- `vendor/vexflow-bravura.js` はリハモ道場(cellish/reharm-dojo、公開リポジトリ)と同じ VexFlow 5.0.0。グローバル `VexFlow`。フォントは同梱データから自動で読み込まれる。
- `js/score.js` の `GScore.engrave(model)` が浄書し、`geo`(各スロットの x と枠の左右、定旋律の x、各段の第5線の y と音、半音階1段の高さ)を返す。結果は model の JSON をキーに最大40件キャッシュ。
- 声部ごとに1段。音部記号は加線の数が少ないほう(対旋律は定旋律±5度の予想声域で決め、書いている途中で変わらないようにした)。
- 写した VexFlow の SVG は `<g class="vfw">` に入れる。**`.vfw text{font-family:Bravura,Academico}` が必須**(元の svg 要素の指定が外れるため。これがないと符頭が「≈」になる)。
- 色は CSS 変数から読んで VexFlow に渡す。テーマ切替(prefers-color-scheme・data-theme)でキャッシュを消して描き直す。
- クリック→音高は `ptVF`(対旋律の段の第5線の y と音から換算)。VexFlow が使えないときは従来の手描き表示(`drawStaffLegacy`・`ptLegacy`)に切り替わる。
- 確認: 第1〜5類×上下で表示、クリック位置と音高(第5線=F5、第3線=B4、第1線=E4、下段第5線=A3)、ダークモード、幅390px。

## 3. 既知の問題・注意
- 第4類・対旋律が下で、定旋律が終止音から2度下がって始まる場合など、最初の掛留が規則上成り立たない定旋律がある(タイを切れば書ける)。自動生成では全類で解けることを確認したものだけ採用している。
- 定旋律の自動生成はフックスのものほど自然でないことがある。
- 採点(誤り−10・注意−3)は根拠の弱い目安。
- MIDIの黒鍵は C♯・E♭・F♯・G♯・B♭ に綴る(D♯・A♭ などは入力後に直す必要がある)。
- 解答探索は乱択の深さ優先探索。時間切れで「見つからない」ことがある(第4類の下声で起きやすい)。
